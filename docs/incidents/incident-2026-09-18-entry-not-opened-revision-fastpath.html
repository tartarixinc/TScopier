1. Executive summary (plain English)

A signal provider posted a gold buy setup, then edited the message a minute later to add the full details — entry zone, take profits, and stop loss. The copier handles an edited message differently from a brand-new one. On an edit, it first tries to understand the message with its built-in rules, and only asks the AI if those rules fail.

The built-in rules accepted the edited message because it had a stop loss and take profits and the same direction as before. Those rules never check whether an entry price is present. The rules also do not recognise the format “ENTRY ZONE: 4358” when only a single price is given — they only understand a range like “4358-4360”.

So the copier accepted the signal without an entry price, never asked the AI for help, and could not open the trade. The user saw “No position opened”. No money was at risk.

4. Root cause

  1. Edits take a different code path than new messages. tryApplyMessageRevisionInner (userListener.ts:1983) handles Telegram edits. It first calls tryDeterministicRevisionCompletion (userListener.ts:2306) and only calls the AI if that returns null (userListener.ts:2056).
  2. The revision fast-path does not require an entry anchor. revisionHasDeterministicActionableParse (signalRevision.ts:238) accepts a revised parse when the action is buy/sell, it carries explicit stops or targets, and the prior action is null or the same direction (signalRevision.ts:258-266). It never checks for entry_price / entry_zone_low / entry_zone_high.
  3. The parser does not read ENTRY ZONE: <single price>. extractOptionalEntryAnchor (parseSignal.ts, single-price block at line 1108) understands entry price:, entry:, entry level:, @price, buy at price, and two-price ranges — but not a single price after the words “ENTRY ZONE”.
  4. Result: a buy signal with SL/TP but no entry was accepted, the AI was never consulted, and dispatch failed with entry_not_opened.

6. The fix (applied)

  • A. Parser gap. parseSignal.ts — added a single-price entry\s*zone\s*[:=]?\s*<price> pattern with a negative lookahead so a range (ENTRY ZONE: 4358 / 4360) is still read as a zone. Also added zone|area and / to the entrySlashZone range pattern.
  • B. Revision fast-path. signalRevision.ts — both revision helpers now return false when the message labels an entry (helper messageLabelsEntryAnchor) but the parse has no anchor. A genuine market entry (“Gold buy now”, no entry label) is still accepted deterministically.
  • C. Fast-lane guard. universalSignalParser.ts — deterministicQualifiesForFastPath now also returns false for a buy/sell when the message labels an entry the parser missed. The shared helper parsedMissesLabeledEntry backs both B and C.
  • D. Phantom entry from numbered TP/SL @ separators. parseSignal.ts — parseAtPriceExcludingSlTp did not exclude numbered SL/TP labels, so TP1 @ 4256 (and TP 1 @, TP(1) @, TP1: @, Take Profit 1 @) was read as the entry price, which could turn a “SELL NOW” market signal into a limit order at the take-profit price. The exclusion now covers numbered labels with optional separators, mirrored in the guard. The word target is deliberately not in the exclusion list, so an entry written as Entry Target @4235 is still read as the entry (a first attempt added target and broke that case).

Rejected approach: the first attempt required an entry anchor on the revised parse. Review found this broke the legitimate market-entry completion (“Gold buy now” edited to add SL/TP has no anchor by design), and evaluateParsedSignalExecutionEligibility would not have caught the incident either (it returns eligible: true for labeled stops with a zero entry price). The label-gap check avoids both.

11. Follow-ups

  • Commit and deploy to staging, then prod.
  • Consider whether the revision path should also respect a confidence threshold, or always consult the AI when the revised parse lacks an entry anchor.
  • The guard is a regex allow-list; a label neither the parser nor the guard recognises can still skip the AI on an edit. Known residual examples: BUY ZONE 4358, buy area 4358. An inherent limitation to revisit if another such incident appears.
  • LOW: parseSlFromText reads the ordinal in SL2 @ 4276 as the stop price (pre-existing, untouched by this fix).
  • LOW: prose ending in “entry <n>” (e.g. “wait for a good entry 2 hours ago”) is treated as an entry label; the effect is only an unnecessary AI call (fail-safe), not a wrong trade.
